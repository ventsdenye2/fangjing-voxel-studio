# 架构与数据约定

## 组件

React 编辑器只管理可序列化 Project；Three.js 构建可视网格和交互控件。Electron 主进程通过固定 IPC 提供文件选择、设置、BINVOX 转换与导出保存。界面无 Node 权限，binvox 以参数数组启动，不经过 shell。

## 数据

Project schemaVersion=1，包含 assets、nodes、sources。VoxelAsset 保存原点、体素边长、三维尺寸和稀疏坐标到 sRGB hex 颜色。SceneNode 使用稳定 id、parentId、assetId、局部位置/角度/缩放及标签。源文件编码保存在工程包中，跨电脑重开不依赖绝对路径。

坐标为 Y-up，1单位=1米。BINVOX 数据顺序 y fastest、z、x；转换保留 header translate/scale。工程 ZIP 的扩展名为 .vxlproj。源模型重新转换创建新资产版本；复制实例与创建独立资产是两个不同操作。

## 输出

GLB 是交换模型。天工包是面向0.4.19的作者源，通过官方资产烘焙、catalog 和 GUID 加载。玩法逻辑应留在宿主游戏组合层，避免美术重新导出覆盖。出生点和触发区域是标记数据，不自动添加游戏行为。

## 性能与错误

512网格本身有134217728个位置，因此解析采用RLE预检和稀疏存储；单资产占用体素预算默认500万，合并表面预算默认100万，均可在设置中调高或设为0取消应用上限。颜色采样分时让出主线程并支持取消。工程和二进制均校验尺寸与内容，不信任上传路径。

## Alpha.5 大场景数据路径

统一 ResourceLimits 从桌面设置同步到前端和 Worker，校验不依赖隐藏的旧固定阈值。源模型面数与转换超时默认不设应用上限；资产、源文件集合、节点数量不设固定上限。单资产网格仍最高512³。

工程归档 v2 将 manifest、每项资产及二进制源文件独立存储，避免整工程单次 JSON.stringify。读取在专用 Worker 完成，支持取消。校验 ZIP 路径、重复条目、声明展开大小、实际尺寸和 CRC，并保留标准 ZIP 格式上限。原始源文件 gzip 由 source-codec 在需要重载时按解压预算读取。工程运行态仍在内存中，不属于完整的磁盘分区流式场景系统。

IndexedDB v2 分开保存场景清单、资产与源模型，利用不可变对象身份跳过未改变的大资源。写入同一事务，失败回滚；快速修改合并为最新待保存快照。旧草稿首次加载后迁移，不删除旧数据后再写。

资产与场景列表仅生成可见行；隐藏分组不生成独占资产显示网格。渲染工作线程保持最多两个小任务或一个大任务，不因取消容量限制而增加并发。
